# 剧情 MCP 改进实施计划

日期：2026-10-22。状态：首批 M0～M2 已实现，M3～M7 待实施。

目标是让查询者找到相关原文、判断证据边界，并核对长任务的资料覆盖范围。
实施涉及 `ikserver-rs/crates/story`；提取器 `zzz-story-extractor` 负责补充确有来源的证据与发布映射。
本文件规划六项改进并记录实施进展；首批后端变更与核验见 [M0～M2 阶段报告](story-mcp-m0-m2-report.md)。

## 起点与完成边界

已完成的查询修正作为基线，见 [现有检索说明](story-search.md)：

- 多词先求同篇完整匹配，无完整匹配时默认明确返回部分匹配；`allowPartial=false` 保留严格 AND。
- 分支回退保持 path、scope、speaker、docId 和版本筛选。
- 3.2 → Chapter230、3.3 → Chapter240 已核对；目录、检索、顺读支持版本别名。
- 上一轮 31 项剧情库端到端测试及相关编译、格式检查通过；线上是否已部署须在实施时单独核对。

本计划完成后，MCP 应能解释结果为何命中、哪些姓名仅来自姓名表、哪些内容是占位或未关联候选，
提供可续接的结构化结果和分页，并计算指定范围的已返回文本覆盖情况。
这不等于恢复完整运行时播放图；语义检索、跨场景实际时间线和自动补说话人不在本轮交付范围。

## 实施顺序

| 阶段 | 对应改进 | 优先级 | 前置条件 | 阶段交付 |
| --- | --- | --- | --- | --- |
| M0 | 固定基线与数据契约 | 必须 | 无 | 回归样例、快照标识、字段与兼容约定 |
| M1 | 1. 提取证据进入 MCP | P0 | M0 | 占位、角色、顺序与资源关联证据展示 |
| M2 | 2. 搜索命中分类与排序 | P0 | M0、M1 | 正文与元数据分开，目录建议独立呈现 |
| M3 | 4. 结构化结果与稳定分页 | P1 | M1、M2 | 类型化结果、MCP structuredContent、快照绑定游标 |
| M4 | 3. 场景窗口与关联上下文 | P1 | M1、M3 | 篇内窗口检索、带证据的相关片段入口 |
| M5 | 5. 整章覆盖核对 | P1 | M1、M3 | 范围清单、已返回区间、未覆盖与候选统计 |

独立形成可审查的变更；M1、M2 是首批最有价值的交付，不必等待后续全部完成才验证。

## M0：建立可复现基线

- 固定一个实际存在的 3.3 语料目录或包，记录 SHA-256、筛选模式、来源版本、文档及文本计数。
  实施开始时核查路径，不把历史报告中的已移走目录当成当前输入。
- 建立小型隔离回归语料，并在真实语料上保存查询参数、输出、延迟和内存基线。
  关键案例为 Chapter240 的 32～34 幕占位说明、36～37 幕未关联候选、重复及铃/哲称呼版本，
  以及“天空 核心 秘密”“3.3版本 核心”、姓名命中和标题命中。
- 确定 corpusRevision：由规范化语料内容及影响结果的配置生成摘要，重启或构建时间改变不应导致漂移。
  发布映射和排序规则变化须纳入游标兼容判断。
- 固定现有五个工具、docId、sourceKey、lineId 和读取续接参数的兼容样例。
  对旧包缺失字段、新字段未知枚举值、默认/完整性模式分别建立样例。

验收：相同输入、相同查询在重载后得到相同身份与排列；计划中的回归数据有明确来源与预期，
测试夹具避免复制整章游戏原文。后续 bug 先用失败测试复现，再改实现。

## M1：完整保留并展示提取证据

当前 `corpus/build.rs` 的 Row 没有读取许多提取证据，LineKind 也没有占位类型；
Doc 的姓名集合合并了场景姓名表与逐句署名。先修复这段信息传递，再调整查询表现。

1. 在 Row、DraftLine、Line 旁的证据数据中读取以下可选字段，避免每行复制大段资源 JSON：
   `content_status`、`content_evidence`、`source_attribution`、`speaker_status`、
   `speaker_gap_reason`、`speaker_source`、`speaker_slot`、`has_voice`、
   `line_order_source`、`line_order_status`、Perform/Timeline 引用摘要。
   资源路径及节点位置按需给出，完整证据保持可追溯。
2. 分开保存“逐句已解析姓名”“推断署名”“TextMap 姓名表”，保留原显示名及身份归一关系。
   character 的台词数和实际署名统计只按对应行计算；姓名表关联另列，不能算作实际台词或首次登场。
3. 占位说明保持独立内容类型。原始安比资源标注放在来源证据里，不重新输出为安比正式对白。
   未关联候选保持未知，不因缺资源改为旁白，不凭语意补角色。
4. 在 catalog、search、read、character 中使用一致的简短状态提示。
   默认显示影响理解的缺口；详细来源由可选证据参数展开。过滤占位或未知候选必须显式，默认保留。
5. 将内容状态、署名依据、播放核验、局部顺序及跨场景顺序分开表达。
   `resolved` 只表示姓名字段已关联；`has_voice=false` 只表示未找到配音关联。
   资源引用或局部时间依据均不自动表示实际播放已确认。

主要位置：`corpus/mod.rs`、`corpus/build.rs`、`engine/mod.rs`、`engine/{catalog,search,read,character}.rs`；
必要时在提取器 `narrative.py`、`extract.py` 与导出契约中补摘要字段。

验收：32～34 幕的 5 条占位说明不再署名安比；36～37 幕仍保留 26 条候选、5 组相邻同文及称呼版本，
工具明确显示姓名表和未核实状态。旧包显示“未提供证据”，正常署名与隐藏姓名不被改写。
JSONL → 目录加载/语料包加载 → MCP 均能追溯原文及稳定 ID。

## M2：区分正文命中和元数据命中

当前 `collect_term_hits` 把正文、说话人、身份、标题、路径和姓名表命中并入同一覆盖位图。
“天空”出现在章节路径，部分匹配因此扩展到该章全部 257 篇；这种结果需要说明并调整位置。

1. 为每个词记录匹配字段：正文、逐句说话人、身份、文档标题、章节/路径、姓名表。
   输出正文匹配词、元数据匹配词、全局缺失词，必要时另给“正文缺失词”。
2. 保留当前完整匹配优先、默认部分匹配及严格查询行为。
   兼容的 `matchIn=all` 仍允许同篇元数据参与 AND；新增 `matchIn=body` 可要求正文共现。
   不能把“标题满足天空、正文满足核心”描述成正文同时包含两个词。
3. 结果先展示正文或实际署名相关的命中，再展示仅元数据匹配的目录建议。
   仅章节路径或姓名表命中的条目不占用正文结果配额；给出建议数量与可浏览入口。
   标题查询和角色查询仍能找到原来可访问的文档。
4. 排序先比较完整/部分匹配，再在正文结果内比较正文词覆盖、有效署名覆盖和相关度；
   使用稳定文档标识兜底。若无完整匹配，正文多词覆盖优先于只有泛化标题词的候选。
5. 输出摘要区分候选文档数、正文结果数、目录建议数和命中行数。
   版本词仍是范围选择，单独搜“3.3”展示章节目录，不伪装成正文命中。

主要位置：`engine/search.rs`、`index.rs`、DocKeys 与文档元数据索引；同步工具描述和 guides。

验收：“天空 核心 秘密”不再把全章 257 篇描述为正文结果；标题独有命中仍有读取入口。
所有结果逐词说明匹配字段；严格 AND、body-only、篇内查询、speaker 筛选和大小写/全角折叠通过反例测试。
回退不跨章节、文档或 scope，不丢重复原文。

## M3：结构化结果与快照绑定分页

1. 引入类型化工具响应，由统一响应生成可读文本和 `structuredContent`，避免反向解析文本。
   保留原有 text content，旧客户端仍可读；在 MCP 定义中添加相应 outputSchema。
2. 共同字段包括 schemaVersion、corpusRevision、快照版本、提取模式、解析后的范围、证据提示。
   检索项含 docId、匹配字段、缺失词、行号、sourceKey/lineId、结果类型与证据摘要。
   read 输出本次确实返回的行区间和续接信息；catalog/character 提供相同身份与状态。
3. 搜索增加不透明 cursor 和 nextCursor。游标绑定快照、规范化查询、筛选参数及排序版本；
   同快照内固定排序和分页边界，分页期间不重新扩大筛选范围。
   格式错误、超长游标、参数冲突和快照切换明确返回重查指引。
4. 先保持服务无会话、无新增数据库表；分页按当前快照确定性计算。
   目录/正文结果各自清楚分页，不能截掉目录建议却声称全结果已显示。
   已有 maxResults、hitsPerDoc、contextLines 和读取偏好继续生效。

主要位置：`engine/mod.rs`、各工具响应类型、`mcp/mod.rs` 的 CallToolResult、`mcp/tools.rs`；
游标编解码独立模块。M0 的身份契约决定其快照绑定方式。

验收：text 与结构化数据来自同一结果、数量和来源一致；翻完全部页面无漏项或重复。
服务重载同一语料能继续分页；切换语料拒绝旧游标。MCP JSON-RPC、HTTP、本地 query 和旧客户端路径均通过。

## M4：场景窗口与关联上下文

1. 增加 `matchUnit=doc|window`，默认保持同篇检索；window 模式使用有上限的连续原文行窗口，
   检查全词/部分覆盖并返回最小覆盖区间、各词行号与局部顺序依据。
   `contextLines` 继续负责展示邻行，不能和窗口匹配条件混为一谈。
2. 合并相互重叠的展示窗口，保留每条源文本与引用身份；不按文本内容删除不同来源的重复项。
   仅有来源键排列时称为“文档行窗口”，不称为实际连续播放。
3. 可选返回 relatedDocs。关联类型分开记录为共同任务、共同资源、已核验执行边等，附来源和状态。
   共同任务或资源只说明关联；不能据此标记剧情前后关系。
4. 跨文档内容独立成块，每块提供 docId 和来源。多个片段中的词不能合起来宣称同篇全词匹配。
   未关联 Comic、无资源的36～37幕及未知性别/条件分支不按目录邻接自动拼接。
5. 现有证据不足时先交付篇内窗口和相关入口。新增跨文档关系须由提取器导出可验证关系；
   对暂无证据的输入返回关联未知，不阻塞基本窗口工具，也不伪造关系。

验收：同篇跨行概念可定位；窗口边界、跨分支、重复引用、多资源反例均可复现。
跨片段必须有类型化关联依据；用户能区分文档邻行、任务相关和已核验执行关系。

## M5：整章资料覆盖核对

1. catalog 可生成绑定 corpusRevision 的范围清单，固定章节、内容类型和证据过滤选项。
   给出总文档/行数、占位数、未关联候选数；明确计数交叉关系，避免重复相加。
2. read 在结构化响应中返回 coverageDelta：文档身份、实际返回的完整行区间及截断状态。
   搜索片段、标题卡片不能计为整篇已返回；未全文展示的截断行不能计为完整行覆盖。
3. 添加只读 `ik_coverage` 工具，接受范围清单标识及调用者保存的已返回区间记录，
   合并重复与交叠区间，计算已覆盖、部分覆盖、待获取及显式排除项，输出下一批读取入口。
   工具校验区间与快照一致，不维护服务器阅读会话或写数据库。
4. 覆盖统计标为“调用者提交记录所描述的已返回资料”，不能声称模型已理解、历史请求已被服务器证实。
   客户端依据 read 的 coverageDelta 更新记录，长任务可持久化并续接。
   批量输入、未覆盖清单和输出均设上限与分页，避免整章行列表挤占模型上下文。
5. guides 在全章总结前要求核对范围及待获取清单；总结引用仍使用原文身份。
   占位说明、未关联候选默认在清单中可见，过滤后需报告排除数量和原因。

主要位置：`engine/catalog.rs`、`engine/read.rs`、新增 `engine/coverage.rs`、MCP 工具定义与 guides。

验收：分页及 follow 返回区间可累计；重复读取不增加覆盖，局部读取不算整篇，
换快照拒绝旧记录，遗漏一个场景仍能显示待获取。统计与原始范围行数、过滤去向对账一致。

## M6：扩充经过核验的版本目录

1. 将当前两个硬编码映射演进为有来源的数据表，最少记录 releaseVersion、aliases、
   addedMainStoryGroups、章节标题、来源地址/文件/提交、核验日期与状态。
   一个版本可新增多章，也可没有新增主线，不能规定每版恰好对应一章。
2. 分别表达发布版本、语料快照版本和故事季/章。旧映射保持兼容；
   `3.3%` 等普通文本继续作为原文检索，版本表达式不能吞掉任意数字短语。
3. 提供发布目录入口，说明已核验覆盖范围。新增模式区分“该版新增主线”和“当前快照中已收录内容”。
   若要回答“截至某版本有哪些章节”，必须有逐章发布记录，不能把当前快照所有章节倒灌到历史版本。
4. 从可核对的历史快照差异、官方发布资料等收集映射。冲突或缺资料标为待核验；
   不以当前模型记忆或发布周期自动补齐。别名支持中文、v前缀和已核对补丁版本。
5. 映射缺失、已知章节在当前语料不可用、多章范围和互相冲突的显式范围各有明确结果。
   多章选择与 M3 分页、M5 范围清单共用解析契约。

主要位置：`engine/releases.rs`、新增版本数据文件及校验、catalog/search/read 的范围解析；
提取器 manifest 可携带经核查的发布记录，后端兼容缺省旧包并避免两个来源静默冲突。

验收：现有3.2/3.3结果不回退，单版多章/无主线/未核验版/缺失章节均正确显示。
每条新映射有可追溯依据；最终报告列出实际核验覆盖的版本，不承诺补全无法证实的历史。

## M7：集成验收与发布

- 质量：复查六类用户案例及反例；原文、sourceKey、lineId、文档身份和不确定候选不丢失。
  证据从目录加载和 gzip 语料包加载到 MCP 均一致；混合旧/新字段行为明确。
- 兼容：五个现有工具调用、数字/布尔字符串、未知参数、分页偏好、MCP 文本客户端通过回归。
  新结构化字段、游标、窗口和 coverage 工具通过协议/HTTP 测试；文本和结构化计数一致。
- 性能：M0 固定语料上比较构建时间、驻留内存、查询 p50/p95、响应大小。
  正常词、单字泛词、只命中标题、全章范围和长游标分别测量。目标相对基线 p95/内存增幅不超过20%；
  超过时先分析分配和索引开销，若需调整目标，给出实测与取舍说明。
- 检查：按 AGENTS.md 运行改动相关的 story 测试、`cargo check -p ik-story --all-targets` 和格式检查；
  本地不跑工作区全量/数据库测试或完整 clippy。实际有提取器代码变更时补相应 Python 测试及语料完整性核验。
- 发布：先准备审查变更、工具契约、语料兼容性说明、回滚材料和真实查询报告，再进入后端发布。
  只有另行获得发布授权才执行线上操作；当前首批任务完成本地实现与核验，不执行线上发布。
- 上线核验：工具定义刷新、部分匹配/证据/别名/分页的只读冒烟检查，确认运行版本与已审查构建一致。

最终完成标准：查询者能从 MCP 直接知道命中字段与证据状态，稳定取完指定结果，
用明确边界获取上下文，并核对章节范围中的资料覆盖；未知播放关系和无法核验的版本仍明确保留未知。
