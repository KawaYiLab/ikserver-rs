# ADR 0006：扁平评论——取消楼中楼，所有评论平等占一层

- 状态：已接受（2026-10-24），取代 comments.md 的单层楼中楼结构（`CMT-025`、`CMT-026`、`CMT-048`、`CMT-052`、`CMT-057`、
  `CMT-060`、`CMT-064`～`CMT-070`、`CMT-074`、`CMT-091`、`CMT-136`）与 D-004 方案 A
- 背景：旧结构把评论分成两等。一级评论有楼层号、能置顶和采纳；回复挂在一级评论下面，没有楼层，列表里只内联前 3 条，
  要点「展开」才能看到其余的。由此带来几个问题：
  - 「回复某条回复」只是在正文开头塞一个提及，`parent` 仍指向一级评论，楼里聊多了看不出谁在回谁；
  - 删除一级评论会把下面所有人的回复一起硬删除；
  - 一条一级评论火了，它下面就成了评论区里的评论区，后来单独发的评论被压在下面；
  - 一级评论和回复各有一套分页（列表倒序、回复按游标正序）、一套映射，客户端也是两套交互。

## 决策

改成 Discourse 式的线性时间线：

1. **每条评论都占一个楼层**，按发表顺序从 1 开始，从旧到新排。楼层号在锁住帖子行后由 `posts.last_comment_floor`
   递增分配，删除评论（包括最后一层）不回收，号码永不重复。
2. **回复只是一条带引用的普通评论。** `comments.reply_to_id` 可以指向本帖下任意一条未隐藏的评论（包括回复），
   同时快照被回复评论的楼层号 `reply_to_floor`。列表里每条评论带 `replyTo { floor, deleted, comment? }`
   （原评论摘要：作者 + 80 字纯文本）和 `replyCount`（收到的可见回复数），点开用 `GET /v1/comments/{id}/replies` 看回复它的评论。
3. **删除不再级联。** 被回复的评论删除后，`reply_to_id` 由外键置空，`reply_to_floor` 保留，客户端显示「回复 #12 · 原评论已删除」。
   被隐藏的、作者与读者有拉黑关系的原评论，引用里不带摘要（`deleted = false`，`comment = null`）。
   回复本身的可见性只看它自己：原评论被隐藏不再连带隐藏回复。
4. **置顶、采纳对所有评论开放。** 第一页额外返回 `accepted` / `pinned`，它们在时间线里照常出现在自己的楼层。
5. **列表接口**：`GET /v1/posts/{id}/comments` 按楼层正序，游标里记楼层号；`anchor=<评论 id>` 从那条评论所在楼层开始，
   并返回 `prevCursor` 往前翻（通知、链接跳转用）。回复分页同样按楼层。
6. **通知**：直接评论帖子通知帖主（`comment`），回复某条评论通知它的作者（`reply`），回复「回复」时通知的是那条回复的作者。
   匿名规则不变（被回复的评论匿名时不发）。
7. **AI 评论回复**回复触发评论本身（`reply_to_id = 触发评论`），占一层；触发评论回复的那条作为「父评论」进上下文。
   回复 AI 的任何一条评论都会触发它（TRIG-013 ②）。

## 迁移

`20261112000001_flat_comments.sql` 一次完成：

- 推断旧回复真正回复的是谁：正文以提及开头（旧前端「回复某条回复」时预填的 chip，`CMT-026`）就取同一楼里此前最后一条
  该用户的实名回复，否则是所在的一级评论；
- 每个帖子的全部评论按 `(created_at, id)` 重新编号。旧的一级评论楼层号会变，按评论 id 的链接和通知不受影响；
- `parent_id` 改名 `reply_to_id`，外键改为 `ON DELETE SET NULL`，补上 `reply_to_floor` 与 `posts.last_comment_floor`。

旧数据导入（`crates/legacy`）按同样的规则编号，旧站的「回复的回复」原样保留，不再挂到顶层评论下。

## 兼容

- 发表接口仍接收旧字段名 `parentId`（等同 `replyToId`），没升级的安卓客户端发的回复照常成功。
- 列表接口的响应改了形状（`items` 是扁平的 `CommentView`，没有 `replies`），网页与安卓随本次一起发版。
- `COMMENT_NOT_TOP_LEVEL` 错误码不再出现。搜索索引去掉 `parentId` 字段，下次全量对账（或 `ik-server search reindex`）后生效。

## 后果

- 评论区只剩一条时间线、一套分页和映射；热门评论不会再吞掉后来的评论。
- 评论之间的对话靠引用串起来，没有嵌套层级；需要看完整对话链时，客户端可以沿 `replyTo` 逐条往上找。
- 帖子评论数只随被删的那一条变化（不再一次扣掉整楼）。
