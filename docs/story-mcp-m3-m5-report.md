# 剧情 MCP 调用体验改进报告（M3～M5）

2026-10-22：本轮已实现统一结构化结果、快照续接、任务预设、篇内窗口、批量读取和覆盖核对。六个工具共用返回契约，适用于不同章节、角色及新旧语料；没有针对某个关键词写特殊逻辑。版本解析继续使用已经核查过的3.2/3.3映射。

## 模型可以少做哪些事

| 原来的操作负担 | 当前行为 |
| --- | --- |
| 从文本卡片提取ID、行号、数量和证据状态 | `structuredContent`返回类型化数据，六个工具提供Rust生成的`outputSchema`，保留旧text content |
| 翻页时重新拼关键词、范围、分页和证据参数 | 搜索/目录/读取返回可执行`nextCall`；仅带回cursor，正文与目录分别续页 |
| 每次阅读冗长的统一警告与逐词说明 | MCP默认compact，full展开说明，includeEvidence展开证据；文档/行保留影响解读的状态 |
| 不清楚找出处、查证应选哪些参数 | browse/locate/verify任务预设，显式参数优先；空结果给出保留范围的重查调用 |
| 同篇出现多个词就误认为局部共现 | window模式求有上限的最小文档行区间，邻行展示不补足匹配条件，保留局部顺序来源/状态 |
| 多个小场景逐个读取 | `ik_read(docIds=[…])`最多16篇，共用预算，每块保留文档与来源身份，游标自动推进 |
| 手工估计章内是否漏读或重复计算 | catalog生成固定范围manifest，read返回完整行coverageDelta，ik_coverage合并重复/交叠记录并返回缺口与nextRead |

这些机制降低参数组装和资料核对负担。覆盖统计只描述调用者提交记录中的完整返回行，客户端负责累计和持久化ledger；不证明模型理解，也不验证服务器历史请求。当前没有接入外部MCP客户端的自动记账逻辑。

## 契约和边界

- 返回信封包含schemaVersion、corpusRevision、snapshotVersion、extractionMode、data；证据/来源不反向解析文本。详细目录的兼容展示仍复用既有渲染逻辑，选中范围和页大小与结构化数据一致。
- 无服务器阅读会话或新增数据库表。游标包含规范化偏好和快照摘要，校验长度、格式、版本、工具、参数冲突与语料切换。同一有效语料重新加载可续接；不同快照要求重查。校验和用于发现损坏，不是授权签名，HTTP鉴权继续独立生效。
- window默认12行，上限100行，区间基于文档行序。不同来源的重复原文及条件候选保留；orderStatus为playback_unverified，relatedStatus为unknown。跨文档播放关系仍需提取器提供可验证执行证据。
- 全库每篇只展示配额内的行/窗口；nextMatches提供篇内更多命中入口。搜索片段超过180字时截断并设complete=false；行号列表、窗口、角色章节及20行证据预览均标记截断。全文覆盖只来自read的完整返回行，missing缺口使用独立类型。
- manifest限定path/scope及整篇排除选项。默认包括占位和未关联候选；只有整篇全部为某类行才会被对应选项排除，混合文档保留。状态计数可能交叉，不能直接相加。范围内覆盖、显式排除与总行数分别对账。
- coverage最多接收512段记录，待获取文档默认20篇、上限100篇分页，返回合并ledger。更大任务先合并记录或按章节拆分。read首行过长时完整返回以保证推进，之后受预算约束。
- 旧本地query/`tools::call`默认详细文本，MCP默认compact。HTTP路由及DTO没有变化，无SQL/迁移/`.sqlx`变更，既有OpenAPI动态JSON-RPC契约不变。

## 真实资料工作流

固定输入为本机提取器`out/zzz_story_3.3.0_chs`，8,649篇、155,708行、12,553,056字节原文。包SHA-256与M0～M2一致：

`8a48142a277c31d9a889ce412618e009f0aa19b47f2bd501fe32d105ebdec9ba`

查询契约更新后corpusRevision为：

`corpus_v1_7f9b051811aacbdf865de27b04a17267f850191f9f1273e1489db06bc5fdc56d`

“天空 核心 秘密”限定3.3，仍是257候选、13正文/署名结果、244目录建议。目录配额50篇时5次调用取完244篇，重复为0。合成测试另外验证正文分页、目录分页、窗口/命中行分页均没有遗漏或重复。

整章流程使用1次catalog(manifest=true)、3次read(maxChars=30000)、1次coverage。实际返回257篇、2,149行；完整257篇、部分0篇、未读0篇。3次读取RPC总计975,247字节，包含兼容文本、结构化行及文档元数据。没有把目录顺读解释成剧情时间线。

这是确定性工具工作流评测。没有运行真实模型回答质量、token计费、引用正确率或模型是否愿意优先调用的A/B评测，不能据此承诺所有模型/客户端更省token。

## 响应大小与性能

Windows GNU Rust1.99.0、dev构建、每个查询25次。工具清单含全部input/output schema共25,853字节；按工具裁剪无关schema引用，启动后缓存清单。

| 查询/操作 | MCP compact文本字节 | 同参数full文本字节 | 完整MCP RPC字节 | MCP p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 天空 核心 秘密，3.3 | 9,998 | 16,028 | 37,478 | 7.265 |
| 3.3版本 核心，locate | 2,255 | 3,876 | 8,591 | 1.656 |
| 天空 核心，verify/window=12 | 713 | 1,136 | 1,796 | 0.272 |
| 单字核，3.3 | 8,384 | 13,748 | 30,830 | 3.935 |
| 3.3目录，100篇 | 16,573 | 26,488 | 48,736 | 2.468 |
| Fairy角色速览 | 1,949 | 17,185 | 20,381 | 6.714 |
| 3.3顺读，20行 | 2,389 | 3,160 | 9,766 | 0.548 |

上一阶段示例查询详细文本21,849字节，本轮MCP默认文本9,998字节，约缩短54%。完整RPC则为37,478字节，增加结构化行、来源及续接参数后，传输量高于旧纯文本。客户端宜选一种主要表示提供给模型，避免重复注入同一批原文；这需要客户端配合，服务端兼容输出本身不能保证token下降。

同一旧测量入口另做了对照，保存在metrics的same_harness_text_comparison。天空 核心 秘密p95为3.834→3.892ms，核心1.142→1.012ms，严格天空1.262→1.827ms，Fairy1.732→1.503ms，单字核2.730→2.989ms，目录0.249→0.693ms，read20行0.026→0.076ms。两种测量入口的序列化工作不同，不能混算涨幅。该对照在收尾的截断字段/更多命中入口补齐前运行，字节数不等同于上表最终MCP响应。

同测量入口构建约9.746秒、WorkingSet64约184.6MiB，上一阶段为10.826秒/183.5MiB。新工作流入口约10.151秒/109.8MiB，驻留采样包含不同分配器保留空间和执行轨迹，不能把两个入口相减称为内存优化。目录/read及部分查询相对增幅仍超过20%目标，**M7性能验收尚未统一通过**，没有调整目标或声称全面提速。

## 验证和复现

31项原端到端、9项改进、18项调用体验测试通过；2项游标单元/性质测试通过，共60项。真实语料测量测试显式运行通过。缺陷反例先失败再修复，包括续页/coverage缺失、窗口页重复、非最小窗口、邻行重复标命中及正文误报推断署名。

已用JSON Schema Draft2020-12校验全部6份生成schema与13份记录响应。`cargo check -p ik-story --all-targets`、`cargo fmt --all -- --check`和`git diff --check`通过。未运行工作区全量/数据库测试或完整clippy。
