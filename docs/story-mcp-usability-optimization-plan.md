# 剧情 MCP 默认输出与调用体验优化方案

日期：2026-10-22。状态：U0/U1/U2及U3导航已实施并本地核验；U3聚合待等价证据；性能目标与真实模型验收未完成。

基线为后端提交 `5691f5a`（M3～M5）及本机 3.3.0 语料。目标是让只接收 MCP 文本的模型也能确认
语料版本、证据边界和下一步调用，同时保留精简输出。结构化客户端应获得同样的信息，避免再次出现
“数据仍在服务端，调用者却看不到”的退化。

本方案接续 [原实施计划](story-mcp-improvement-plan.md)，针对公共 MCP 默认输出遗漏和调用体验。
发布版本目录扩充仍归 M6，完整性能与真实模型验收仍归 M7；不重复建设另一套检索或覆盖机制。
实施结果与成本见 [实施报告](story-mcp-usability-optimization-report.md)。按用户明确范围，不开发 AstrBot、Gemini
或其他客户端专用适配、模型分支或自动账本；公共 text 与 structuredContent 提供一致的关键事实。

## 已核实的起点

| 反馈 | 当前实际情况 | 本轮处理 |
| --- | --- | --- |
| 输出显著压缩 | 示例搜索文本从 21,849 降到 9,998 字节，约减少54%；完整RPC为37,478字节，未实测模型token | 保留compact，分别测文本、RPC和实际上下文 |
| cursor与精确续读 | 已实现，游标封装参数并绑定快照；服务端无阅读会话 | 保留并补齐单篇读完后的导航 |
| speaker过滤新增 | 更早提交已经支持 | 作为回归能力，不列为新功能 |
| ch:报错 | 合法完整ID可用；裸前缀、未知ID和歧义输入没有具体候选 | 增加可直接执行的纠错提示 |
| 版本溯源消失 | structuredContent仍有快照版本、corpusRevision与提取模式；compact文本缺失；版本别名解析保留 | 恢复默认可见的短摘要和别名目录 |
| 逐篇顺序信息退化 | 普通Document缺少顺序字段；窗口检索另有局部顺序信息 | 将篇序、行序和剧情先后分别补入公共文档卡 |

| 说话人覆盖率不显示 | full根目录仍显示，compact和公共结构化目录缺少明确统计 | 返回计数、分母、署名状态及覆盖范围 |

`crates/story/src/engine/{response,catalog,read}.rs`、`corpus/{mod,build}.rs` 与 `engine/releases.rs`。
本机实测报告描述本地实现，不证明线上或另一位AI使用的服务已经运行同一构建。

## 默认输出契约

以下为已实施的公共输出契约。原则是“每次响应一份快照摘要、每篇一份短状态、每行只写必要标记”。
`full` 展开解释与名单；`includeEvidence` 展开逐行核验证据；`includeSources` 保持读取来源键的现有行为。
影响结论的未知、占位、推断和未关联状态在compact中也必须可见。

### 1. 每次响应都能确认版本与实际范围

- 六个工具成功响应的文本头部增加一行：`语料=3.3.0 | 模式=default | corpusRevision=<完整值>`。
  版本缺失显示“未声明”，不从章节编号推断；每次只输出一次，不在每个文档块重复。
- 保留已有结构化 `schemaVersion`、`snapshotVersion`、`corpusRevision`、`extractionMode`。
  完整revision可用于复制与对账，不用截短值代替身份。
- catalog/search/read的类型化数据新增可选公共 `rangeInfo`，记录请求选择器、解析后的分组ID、
  选择模式以及使用版本别名时的发布版本。既有 `resolvedRange` 不改类型、不改语义。
  请求为“3.3版本”时默认文本写明：`范围=3.3新增主线 → ch:Chapter240`。
  直接输入精确ID也显示实际范围；多篇批量读取按块保留各自所属分组。
- 根目录增加 `releaseAliases`，列出已核验3.2/3.3映射及当前语料是否包含目标章节。
  缺失章节仍显示“已知映射、当前未收录”；不得为历史章节自动填入快照版本。
- 默认目录文本显示 `manifestId` 及清单总行数；read每块用docId、起止行和完整行标记表达coverageDelta，
  与头部revision共同组成可提交区间，不重复整段JSON。coverage文本明确完整/部分/未读计数与缺口入口。
  外部纯文本模型的自动记账由调用者实现，服务端必须提供清单标识与完整返回区间。

### 2. 每篇都有可区分的顺序与证据摘要

公共 `Document` 新增可选 `order` 和类型化 `evidenceSummary`，同时保留已有 `evidenceHints`。
order从现有文档和行证据生成，至少包含：

| 字段 | 来源与含义 |
| --- | --- |
| docOrderSource | Doc.order_source；只说明文档排列的依据 |
| lineOrderSources | 聚合该篇LineEvidence.line_order_source及各来源行数；缺字段单列为未提供 |
| lineOrderStatuses | 聚合局部行序核验状态及行数；保留未知枚举原值 |
| chronologyStatus | Doc.chronology_status；只说明跨场景剧情先后核验状态 |
| contextStatus | Doc.context_status；说明片段是否已关联上下文 |

不能把行的 `source_key` 当成篇序依据，也不能把 `archive_table` 排列当成实际播放顺序。
这些轴即使缺证据也分别显示未知；设定文档显示“不适用”，不伪装成剧情顺序。

catalog/search/read/character展示文档时，一篇只显示一行摘要，例如：

```text
篇序=archive_table | 行序=source_key | 剧情先后=unknown | 未关联候选=6
```

摘要覆盖整篇，search的窗口状态则只覆盖该窗口，两者须注明范围。混合来源不得只取首行；默认文本最多
展示3种来源，超过时标明“混合，共N种，full查看”，结构化计数完整保留。证据统计只展示非零缺口，
计数可能交叉时明确标记，禁止将未知/缺失、未关联、无配音直接相加。
不重复刷TextMap姓名表；名单由full展开，影响理解的姓名表关联仍用短状态说明。

### 3. 署名名单与覆盖统计有明确口径

- `Document` 新增可选 `speakerSummary`，包含逐句署名姓名预览、总人数、名单是否截断，
  推断署名单独统计。compact最多显示6个逐句署名姓名，full展开完整名单。
  标签用“逐句署名”，不把姓名表、提及或推断改称确定出场；旧包署名注明缺少核验证据。
- catalog根目录与所选章节返回 `speakerCoverage`；read返回块所属整篇统计。
  根目录现有比率的分母是主线全部行，恢复展示时明确标作“主线全行署名率”，不改称对白准确率。
  新统计同时提供计数与分母，并标明范围、内容类型、整篇排除条件。
- 对范围内每行按“有名字且resolved”“有名字且inferred”“有名字但旧包未声明状态”
  “有名字但其他/未知状态”“无名字”划分互斥计数；五类之和等于范围总行数。
  有名字率为前四类之和除以总行数。已解析姓名不表示播放已核实。
- 占位、选项、旁白仍属于全行分母；若另提供可归属对白率，必须单列可归属行数与判断依据，
  不能混用两个分母。无可靠分类的旧包不计算这项附加比率。
- “未提供核验证据”“未关联候选”“未找到配音”是另外的缺口指标，允许与署名分类交叉。
  分母为0时显示“不适用”。不只返回四舍五入的百分比。

统计优先在语料加载时按文档计算，按目录范围聚合；搜索只为本页展示文档构造摘要，
分页不改变范围统计，不在每次搜索重扫整库。
正文命中数、已返回阅读覆盖和署名覆盖保持不同概念。

### 4. 单篇读取完成后仍能继续

- `ReadResult` 新增可选 `nextDocument`：仅包含docId、标题、groupId、
  `relation="catalogAdjacent"` 和可执行 `nextRead`。使用轻量对象，不递归嵌套完整Document。
- 单篇目标已读完且同组还有下一篇时，compact和结构化数据都返回该入口，文本写明
  “下一篇（目录相邻）”。章末写明到达目录末尾，不默认跳入另一章。
- 页内未读完优先给现有 `nextCall`；章节/follow读取继续使用快照cursor。
  batch继续只沿请求的docIds和nextCall推进，避免混入未请求的目录下一篇。
- `complete` 保留“当前指定续读目标已到末尾”的原语义；单篇complete=true仍可能有nextDocument。
  不为提供导航而把它改成整章是否读完。整章资料覆盖继续由ik_coverage核对。
- 所有读取入口保留显式行数、字数、行号、来源、证据及detail偏好，offset重置为1；
  不改变speaker筛选或搜索回退范围。导航不能把目录相邻标成剧情后继。
- 将现有follow预算判断与最终compact渲染统一：预算计入实际文本头、短状态与正文，避免先构造full样式
  再清空重渲染导致分页偏差。沿用首行过长完整返回以保证推进的例外，续接提示另行计量。

## 输入纠错与章节导航

### 无效或歧义输入给出具体下一步

保留完整ID、章节token、大小写/全角规范化、已支持的唯一标签匹配和版本别名。
只有解析失败或歧义时生成建议，不因模糊相似而自动选章或扩大查询范围。

| 输入 | 返回行为 |
| --- | --- |
| path="ch:" | isError=true；说明缺少章节，给根目录调用和至多5个可用章节入口 |
| path="ch:Chaper240" | isError=true；依据ID相似度给出包含ch:Chapter240的候选及完整重试调用 |
| 同名章节标签 | isError=true；列出全部匹配的数量，最多5个候选ID、标题、篇数和重试调用 |
| 未收录的完整章节ID | 说明当前快照未收录；给现有候选，不伪装成成功或空正文 |
| 未核验版本 | 保持“无已确认映射”的错误，列已核验版本入口，不按数值接近猜测版本对应章 |
| 损坏/过期cursor | 保持现有重查错误，不尝试模糊修复token |

建议使用共同范围解析器，在catalog/search/read行为一致。ID拼写用有界编辑距离，标签用规范化包含/相似度；
稳定ID作为同分排序依据。候选数量有上限，排序确定性，不扫描原文、不调用外部模型。
重试调用只替换错误的范围参数，保留其他合法筛选和分页偏好。
第一批继续现有错误text与isError形态，在文本中给完整工具调用；不冒充成功数据。
若后续增加类型化错误建议，需独立生成并验证错误schema，不能直接塞进当前只描述成功结果的outputSchema。

### 旧编号先建立有来源的关联

新增可选目录 `chapterRelations`，记录成员groupId、关系类型、核验状态和来源。
区分“同一章的不同原始编号”“正章与间章”“补充归属”“待核验同名分组”，原始groupId和docId继续可用。

- 优先核查04/040、05/050、052/058等同名分组的提取规则、任务与资源来源。
  02/025和05/055在当前manifest分别标作正章/间章，不预设它们可合并。
- 首批只在根目录补关联说明与成员入口，不改变现有精确ID、标签解析、目录排序和清单范围。
  未核验关系明确标记，不把同名关系自动升级为章节等价。
- 只有证明属于同一产品章节的分组才提供可选聚合入口。聚合选择器使用新的命名空间，
  例如 `chapter:<经核验的逻辑ID>`，不占用现有原始token；默认仍按现有分组访问。
- 聚合结果按原分组分段，保留原始路径/身份，manifest固定成员；不能凭聚合恢复跨组剧情顺序。
  成员按docId去重，不按正文同文删除候选或分支。
- 后续多组范围会影响search/catalog/read/coverage，作为独立提交接入共同解析器和cursor。
  关系映射纳入revision；变更选择语义时拒绝旧游标，而不是静默沿用旧成员。

来源维护沿用M6的核查方式，实际涉及提取器时同步其导出契约、Python测试和语料验证。
本方案不要求为了后端展示立即重导全部语料；没有证据的关系先保留待核验。

## 输出体积与公共 MCP 验证

服务端继续提供text和structuredContent，保留现有工具名、参数、字段、cursor和来源标识。
不通过删行、删稳定ID或默认隐藏未知候选达成体积目标。

公共新增字段均为可选附加字段，`schemaVersion=1`保持现有兼容契约，由Rust类型更新outputSchema。
仅增加展示字段或缓存派生统计时不改变corpusRevision；缓存放在不参与内容摘要的侧表，
避免给当前参与hash的Doc直接加缓存字段而使同一语料的游标无故失效。
改变匹配、别名解析、排序或范围成员时才更新对应查询契约/映射摘要，明确拒绝不兼容旧cursor与manifest。

1. 先补必要信息，再测额外开销。共用Snapshot、Document摘要与读取块渲染，减少重复说明及无意义对象构造。
   候选数、目录建议数和未展开条数必须可见；名单和资源详情按需展开。
2. 确定性测试分别检查text与structuredContent；只接收text时也能找到版本、顺序状态和可执行续读。
   公共契约不依赖调用者猜测隐藏字段，也不依赖某个客户端对响应的特殊投影。
3. 服务端保留两种结果表示；调用者如何注入模型由其自行决定。测量报告区分文本、结构化数据与完整RPC，
   不把字节数或某个客户端表现推广成“所有MCP客户端都省token”。
4. 长任务由调用者保存manifestId、cursor与coverageDelta，合并ledger后核对范围；
   服务端不增加阅读会话或数据库表。自动保存不属于本轮服务端实施。
5. 真实模型A/B需要独立模型调用条件，本轮未调用外部模型；后端回归不能替代实际输入token与模型质量验收。

### 测量与验收口径

- 固定与基线相同的语料包、构建模式、机器、查询参数、页大小和测量入口。
  记录包SHA-256、后端提交、corpusRevision、客户端版本、模型及token计数方法。
- 分别记录text字节、structuredContent字节、完整RPC字节、工具定义字节、模型实际输入token、
  完成整个任务的调用次数和累计token。字节减少不等价于token减少。
- 正常查询、单字泛词、目录100篇、短篇全文、长篇分页、混合顺序来源、角色查询、歧义/错误输入分别测。
  至少包含当前“天空 核心 秘密”“3.3版本 核心”和完整3.3章工作流。
- 必要摘要的文本新增开销目标：每次响应固定部分不超过300个Unicode字符，每篇摘要不超过180字符；
  不含原文、既有路径、可执行调用及full详情。若字段超过预算，明确截断标记和完整查看入口，保留关键状态。
- 同一M3～M5基线下，固定代表任务的确定性工具调用次数目标不增加，候选/原文/覆盖计数保持一致。
  预算临界反例优先保证实际文本预算与游标正确推进；增加摘要导致多一次调用时记录原因和成本，
  不通过超预算或丢字段达成调用次数目标。
  完整任务输入token目标不高于当前默认链路；若当前本已单份注入而补字段使token增加，
  报告实际增量及新增判断能力，不能宣称已达到省token目标。
- 对本轮新增开销，统一入口下p95与驻留内存增幅目标均不超过20%，重复测量至少3轮。
  已有M7未达标项继续单列，不能以本轮未再恶化代替全项目性能达标。
- 真实模型A/B固定任务、模型与提示词，每个案例至少重复3次；评估引用可定位、版本范围正确、
  未把目录邻接当剧情后继、完整读取覆盖和错误后恢复成功，并保存实际可见上下文与用量。
  该阶段需要实际客户端与模型调用条件；完成确定性测试不能代替它。

## 实施顺序与验收

| 阶段 | 优先级与依赖 | 交付与验收 |
| --- | --- | --- |
| U0 固定当前行为 | 必须，先做 | 保存默认RPC/纯文本样例；写版本缺失、混合顺序、单篇缺导航、裸ch:的失败反例 |
| U1 恢复默认必要信息 | P0，U0后 | 公共快照头、rangeInfo、order、evidenceSummary、speakerSummary、speakerCoverage、nextDocument；text/structured关键事实一致 |
| U2 改善输入纠错 | P1，U1后 | 三工具共用建议；裸前缀/错字/歧义可按返回调用恢复，查询范围保持明确 |
